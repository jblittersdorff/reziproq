# MV-01 Mandat-Vorschläge und Mandatsversionen

Version 1.0 · Kapitel 6 · Paket K6-d · baut auf MD-01, ST-01, DL-01 · Bildvorlagen: K6-Mandat, K6-Freigabe (Vorschau) · KN-38

## Ziel

Nach der Freigabe einer Strategie schlägt Reziproq je betroffener Beziehung ein angepasstes Mandat vor. Gültig wird es erst mit Bestätigung der zuständigen Person, als neue Mandatsversion. Laufende Deals bleiben beim Mandat, unter dem sie geprüft wurden.

## Ablauf

1. **Auslöser:** `strategy.release` (ST-01). Ohne festgehaltene Freigabe entsteht kein Vorschlag.
2. **Vorschlag je Beziehung** mit Lieferant in der Supplier Map (Vorschlagen): je Punkt des Mandats heute, neu, Grund aus der Strategie (Hebel, Ziel, Supplier Map) und Status `geaendert`, `neu` oder `bleibt`. Punkte, die bleiben, werden mit Grund genannt.
3. **Zuständig** ist die verantwortliche Person der Beziehung (Demo: Rheintal Jan-Luka, Saar Circuits Paul Hahn, Donau Print und Moldau PCB Tom Berg). Der Vorschlag liegt als Mappe in Heute.
4. **Entscheidung:** Übernehmen (alle Punkte), Einzeln prüfen (je Punkt übernehmen oder ablehnen → `teilweise`), Ablehnen mit Grund. Bindend mit Token. Der Lead der Warengruppe wird informiert.
5. **Neue Mandatsversion** mit Herkunft „Strategie <Warengruppe> <Jahr>, Version x“. Die Stufen „Was Reziproq hier selbst tut“ ändert ein Vorschlag nie.
6. **Unbearbeitet** (E-K6-3): Erinnerung nach 5 Arbeitstagen, nach 10 Tagen Hinweis an den Lead. Bis dahin gilt das alte Mandat.

## Mappe „Mandat <Lieferant> an die Strategie anpassen“ (`/mappe/mandat/<proposal>`)

Kopf mit Herkunft und „nur für euch“; Als Nächstes (Empfehlung von Reziproq); Tabelle Punkt · heute · Vorschlag und Grund · Status; Woher der Vorschlag kommt (Strategie, bisheriges Mandat, Protokoll); Was bleibt (laufende Deals, „<Lieferant> sieht Mandate nie, auch nicht die Änderung“); die anderen Vorschläge mit Person und Status; Leitplanke „Mandatsänderungen gibt immer ein Mensch frei“.

## Daten

```sql
CREATE TABLE mandate_version (          -- Historie, nie überschrieben
  id uuid PRIMARY KEY, relationship_id uuid NOT NULL, version int NOT NULL,
  goals jsonb, limits jsonb, autonomy_caps jsonb,
  source jsonb,                         -- Lieferantenplan-Version, Strategie-Version, proposal_id
  confirmed_by uuid, confirmed_at timestamptz, superseded_at timestamptz,
  space text NOT NULL DEFAULT 'buyer_private',
  UNIQUE (relationship_id, version));

CREATE TABLE mandate_proposal (
  id uuid PRIMARY KEY, mandate_id uuid, relationship_id uuid, from_strategy_version uuid,
  changes jsonb,                        -- je Punkt: heute, neu, Grund, geaendert/neu/bleibt, Entscheidung
  owner_person_id uuid,
  state text CHECK (state IN ('offen','uebernommen','teilweise','abgelehnt')),
  decided_by uuid, decided_at timestamptz, decline_reason text,
  reminded_at timestamptz, lead_notified_at timestamptz,
  space text NOT NULL DEFAULT 'buyer_private');
```

`mandate_proposal` hat zusätzlich `from_share_decision uuid`: Ab Kapitel 8 entstehen Vorschläge auch aus einer Entscheidung über Anteile oder einer Vergabe (SZ-01, VG-01), mit derselben Mappe und denselben Erinnerungen. `mandate.current_version` (MD-01) zeigt auf die gültige Zeile; `mandate_check.mandate_version` (DL-01) hält die Version fest, gegen die geprüft wurde. Beim Übernehmen kopiert der Dienst die gültige Version, wendet die angenommenen Punkte an und schreibt eine neue Zeile.

## Werkzeuge

`mandate.propose_from_strategy` (Vorschlagen, nur nach `strategy.release`) · `mandate.accept` (nur Mensch, Token, neue Mandatsversion) · `mandate.decline` (Mensch, mit Grund) · `mandate.remind` (Erledigen).

## Fertig, wenn

- [ ] T6-15 Ohne festgehaltene Freigabe entsteht kein Mandat-Vorschlag.
- [ ] T6-16 Ein Mandat-Vorschlag nennt für jeden Punkt heute, neu und den Grund; Punkte, die bleiben, auch mit Grund.
- [ ] T6-17 Ein laufender Deal verweist nach einer Mandatsänderung weiter auf die Mandatsversion, gegen die er geprüft wurde.
- [ ] T6-MV1 Ein teilweise übernommener Vorschlag ergibt eine Version, die nur die angenommenen Punkte ändert.
- [ ] T6-MV2 Nach 5 Arbeitstagen ohne Entscheidung kommt eine Erinnerung, nach 10 Tagen ein Hinweis an den Lead; das alte Mandat gilt weiter.
- [ ] T6-MV3 Kein Vorschlag ändert `autonomy_caps`; kein Teil eines Vorschlags erreicht den Lieferanten.

## Nicht Teil

Automatisches Übernehmen; Mandate für Warengruppen als eigenes Objekt (MD-01).
