# ZA-01 Datenräume, Status, Herkunft

Version 1.0 · Kapitel 1 · Paket K1-a (Grundlage), K2-a und K5-a (Rechte) · baut auf dem bestehenden Modell `relationship` · gilt für alle späteren Specs

> **Klärungen aus K0 (24.11.2026, `docs/entscheidungen.md`):** `space` wird für bestehende Tabellen aus Ebene, besitzender Seite und `visibility` abgeleitet; die Policies aus PLT-04 bleiben, die technische Form legt K1-a fest (E-K0-03). `origin` und `confirm_state` sind echte Spalten an den genannten Objekten.

## Ziel

Jedes Objekt einer Beziehung weiß, wem es gehört (Raum), ob beide Seiten es bestätigt haben (Status) und wer es erzeugt hat (Herkunft). Daraus folgen Sichtbarkeit, Kennzeichnung und Rücknahme in allen Kapiteln. Die Trennung wird in der Datenbank durchgesetzt, nicht in der Oberfläche (G-2).

## Daten

```sql
-- relationship bleibt Wurzelobjekt; das Paar ist eindeutig
ALTER TABLE relationship ADD CONSTRAINT relationship_pair_uq UNIQUE (buyer_org_id, supplier_org_id);

-- an jeder Tabelle mit Objekten einer Beziehung
--   (Zusage, Thema, Initiative, Kennzahlwert, Protokoll, Notiz, Dokument, Plan, Termin-Teile, Deal …)
ALTER TABLE <objekt>
  ADD COLUMN relationship_id uuid NOT NULL REFERENCES relationship(id),   -- falls noch nicht vorhanden
  ADD COLUMN space  text NOT NULL CHECK (space IN ('buyer_private','shared','supplier_private')),
  ADD COLUMN origin text NOT NULL DEFAULT 'human' CHECK (origin IN ('human','reziproq','engine','import')),
  ADD COLUMN origin_run_id  uuid,      -- agent_run, wenn origin = reziproq
  ADD COLUMN origin_user_id uuid;      -- wer übernommen oder angelegt hat

-- zusätzlich an geteilten Objekten (Zusage, Thema, Protokoll, Kennzahlwert, Plan, Agenda, Deal-Fassung)
ALTER TABLE <geteiltes_objekt>
  ADD COLUMN confirm_state text NOT NULL DEFAULT 'draft'
    CHECK (confirm_state IN ('draft','buyer_confirmed','supplier_confirmed','both_confirmed')),
  ADD COLUMN buyer_confirmed_by uuid, ADD COLUMN buyer_confirmed_at timestamptz,
  ADD COLUMN supplier_confirmed_by uuid, ADD COLUMN supplier_confirmed_at timestamptz;
```

Migration: bisheriges `org_private` wird `buyer_private`, bisher geteilte Objekte werden `shared`. Herkunft bestehender Zeilen: `import`, wenn aus dem Import, sonst `human`.

## Regeln

1. **Zugriff (Row Level Security).** Eine Person der Käuferorganisation liest `buyer_private` und `shared` ihrer Beziehungen, nie `supplier_private`. Eine Person der Lieferantenorganisation liest `shared` und `supplier_private` genau der Beziehungen ihres Kunden, nie `buyer_private`. Ein Gast per Link (BL-01, BE-01) liest nur die Objekte, die der Link nennt.
2. **Gleiche Regeln überall.** Suche, Frag Reziproq, Exporte, Links, Benachrichtigungen und der Kontext jedes Agent-Laufs gehen über dieselben Zugriffsregeln. Ein Lauf hat die Rechte der Person, für die er läuft.
3. **In die Mitte nur mit Token.** Ein Objekt wechselt von einem privaten Raum nach `shared` nur über ein Werkzeug mit `binding = true` (MA-01) und mit dem Bestätigungs-Token eines Menschen.
4. **Status.** `both_confirmed` erst, wenn beide Seiten bestätigt haben. Was nur eine Seite bestätigt hat, zählt in keiner Quote und keinem Wert (ZQ-01, WK-01).
5. **Herkunft.** Übernimmt ein Mensch einen Entwurf, bleibt `origin = reziproq` und `origin_user_id` ist die Person. Ändert er ihn, gilt `origin = human` mit Verweis auf den Entwurf.
6. **Kennzeichnung** gegenüber der Gegenseite leitet sich aus `origin` und dem Sender ab (AU-01).

## Umsetzung (K1-a.1, 24.11.2026)

- Migration `0130_k1a_datenraeume`. Der Raum je Zeile ist abgeleitet (E-K0-03): `app_row_space(ebene, relationship_id, besitzende Organisation, visibility)`; die Policies aus PLT-04 bleiben unverändert. Neue Tabellen späterer Pakete bekommen `space` als Spalte.
- `origin`, `origin_run_id`, `origin_user_id` an `commitment`, `action`, `jbp_topic`, `initiative`, `kpi_value`, `note`, `meeting_agenda_item`, `meeting_capture`, `jbp_version`. `confirm_state` mit Person und Zeit je Seite an `commitment`, `kpi_value`, `jbp_topic`, `jbp_version`, `meeting_agenda_item`. Das Protokoll bekommt die Spalten mit PR-01 (K3-e), der Deal mit DL-01.
- Abweichung: `origin_user_id` ist `text`, weil Personen Text-IDs aus Zitadel haben.
- Vorbelegung: Herkunft `import` bei Kennzahlwerten aus CSV, sonst `human`. Geteilte Objekte gelten als von der besitzenden Seite bestätigt; freigegebene Versionen des Gemeinsamen Plans als `both_confirmed`. Der Trigger `app_confirm_owner_side` setzt dasselbe für neue Zeilen.
- Token-Schutz: `app_guard_shared` an jeder geteilten Tabelle außer dem Verlauf. Eine Session mit `app.run_id` (Lauf von Reziproq) stellt ein Objekt nur mit gültigem, ungenutztem `confirm_token` derselben Person für genau dieses Objekt in die Mitte. Menschen ohne Lauf bestätigen mit ihrer eigenen Anfrage. `shareOrDraft` (`apps/api/src/modules/spaces/share-guard.ts`) macht aus der Ablehnung einen Entwurf `share_request`.
- Sicht `commitment_rate` zählt nur `both_confirmed` (Grundlage für ZQ-01).
- Tests: `packages/db/src/za-01.test.ts` (T1-ZA1, T1-ZA2, T1-ZA5, T1-ZA6, Token-Schutz an jeder geteilten Tabelle), `apps/api/src/modules/spaces/za-01.test.ts` (T1-ZA3 für Suche, Frag und Export, T1-ZA4).
