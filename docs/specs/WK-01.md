# WK-01 Wert-Engine und Wertkonto

Version 1.0 · Kapitel 4 · Pakete K4-a, K4-b, K4-c, K4-d · baut auf ZA-01, ZQ-01, Impact-Ledger, KI-11 · ersetzt Übersicht (als Wert), W-Uebersicht, KI-Wert-Uebersicht, KI-Wert, KI-Wert-Detail, Kette „Ablauf Ergebnis“ · Bildvorlagen: Uebersicht (Wert), W-Initiative (Wertkonto), W-Pruefung (Mappe), A-Uebersicht · KN-16, KN-18, KN-20, KN-32, KN-33

> **Klärungen aus K0 (24.11.2026, `docs/entscheidungen.md`):** Beträge in Cent mit Währung (E-K0-10); Wertart „strategisch“ ohne Euro, nie in Kacheln oder Summen (E-K0-11); das Controlling bestätigt per Link oder mit Konto (E-K0-12); Ziel je Warengruppe in Cent (E-K0-18).

## Ziel

Wert wird gerechnet, nicht formuliert. Die Wert-Engine bucht aus Regeln und Daten; Menschen geben frei, das Controlling bestätigt. Wert erscheint für beide Seiten im Spiegel; der Wert des Gegenübers ist immer eine Schätzung und nur für die eigene Seite.

## Grundsätze

- Die Engine rechnet deterministisch aus Rechenregel, eingefrorener Baseline und Importwerten. Das Modell schlägt Hebel vor und schreibt Texte, rechnet aber nie eine gebuchte Zahl (G-6).
- Wertarten EBIT, Kostenvermeidung und Cash stehen nebeneinander und werden nie addiert (G-3).
- Gesichert ist ein Wert erst nach Bestätigung durch das Controlling (R5).
- Potenziale mit Sicherheit „niedrig“ erscheinen, fließen aber in keine Summe.

## Reife

R1 Idee · R2 Bewertet · R3 Beschlossen · R4 Umgesetzt · R5 Realisiert (vergibt das Controlling).

## Seiten

**Wert (`/wert`)** – Startseite für Lead und Admin (E-K1-1): Zeitraum Quartal \| Jahr \| Seit Start; Als Nächstes (z. B. Mappe „Wirkung freigeben“); Das Wichtigste mit Satz und Spiegel (für euch gesichert gegen Wert für Lieferanten, geschätzt); Zeilen je Warengruppe (Läuft, Prüfen, Potenzial); drei Kacheln EBIT gesichert, Kostenvermeidung, Cash; Hinweis „nie addiert“; EBIT je Quartal; Wertkonto je Beziehung (für euch, für den Lieferanten geschätzt); rechts „Was Reziproq gebucht hat“, Initiativen nach Reife, Wertbericht. Keine Terminschiene, kein Risiko (Modul aus).

**Wertkonto (`/beziehungen/<id>/wert`)** – in der Akte, Sicht Nur für dich: gebucht je Initiative mit Rechenregel und Status, in Prüfung, Potenziale aus dem Wertfinder (öffnen als Blatt mit Rechenweg, Sicherheit, Nutzen für beide, Daten, die fehlen), Reibung (was das Gegenüber Geld kostet), Beziehungsrendite (wenn eingeschaltet), „Was der Wertfinder geprüft hat“ (Hebel, Marktsignale, Datenlücken). Zeile „Was <Lieferant> sieht“ (E-K0-31): das Gegenüber sieht übernommene Themen und Initiativen mit Nutzen für beide, nie Werte, Rechenwege, Spannen oder die Schätzung für ihn.

**Mappe „Wirkung freigeben“ (`/mappe/wert/<booking>`)** – Rechenweg aus der Engine je Monat, Nachweis, Achtung-Hinweise (z. B. „Ersparnis je Stück sinkt seit Juli“), Optionen Freigeben, Zurückstellen mit Grund, Regel ändern (neue Version); nach Freigabe geht der Nachweis an das Controlling.

## Controlling

Bestätigt per Link mit Token (BL-01, `purpose = value_confirmation`); Konto optional (E-K4-1). Erst danach `state = bestaetigt` und R5.

## Wertfinder (KN-32)

Monatlich automatisch für Fokuslieferanten, sonst auf Knopf „Wert finden“ (E-K4-5). Ergebnis: Potenziale mit Rechenweg aus der Engine, Sicherheit, Nutzen für beide Seiten; als Mappe in Heute, wenn die Wirkung hoch ist. Stufe Vorschlagen oder Vorbereiten.

## Reibung (KN-16)

Ereignisse aus ERP und Verlauf: Eilabruf (Abruf mit weniger als 10 Tagen Vorlauf), Abrufänderung, Reklamation, Wartezeit. Kosten je Ereignisart aus `friction_rate` (Startwerte in den Einstellungen, änderbar durch Lead, versioniert; E-K4-3), als Spanne. Eine Spanne des Lieferanten (DL-01) ersetzt die Branchenwerte für seine Beziehung.

## Beziehungsrendite (KN-20)

EBIT für euch je Stunde gemeinsamer Arbeit. Stunden nur als Summe je Beziehung aus gemeinsamen Terminen und erledigten Aufgaben; nie je Person sichtbar, gespeichert oder exportierbar; keine Zeiterfassung; Stunden des Lieferanten als Schätzung. Standardmäßig aus; der Admin schaltet sie ein, wenn eine Betriebsvereinbarung vorliegt (E-K4-2). Im Demo an.

## Daten

```sql
CREATE TABLE initiative (
  id uuid PRIMARY KEY, relationship_id uuid NOT NULL, title text,
  value_type text NOT NULL CHECK (value_type IN ('ebit','kostenvermeidung','cash')),
  stage text NOT NULL CHECK (stage IN ('R1','R2','R3','R4','R5')),
  rule_id uuid, plan_value numeric, owner_person_id uuid,
  benefit_supplier text, origin text, space text NOT NULL DEFAULT 'shared');

CREATE TABLE value_rule (             -- versioniert, nie überschrieben
  id uuid PRIMARY KEY, initiative_id uuid, version int, formula text,
  baseline numeric, baseline_frozen_at timestamptz, source text,
  space text NOT NULL DEFAULT 'buyer_private');

CREATE TABLE value_booking (
  id uuid PRIMARY KEY, initiative_id uuid, rule_id uuid, period date,
  amount numeric NOT NULL, inputs jsonb,
  state text NOT NULL CHECK (state IN ('gebucht','in_pruefung','freigegeben','bestaetigt')),
  released_by uuid, confirmed_by uuid, space text NOT NULL DEFAULT 'buyer_private');

CREATE VIEW value_account AS          -- je Beziehung und Wertart, ohne Gesamtsumme
SELECT i.relationship_id, i.value_type, b.state, sum(b.amount) AS amount
FROM value_booking b JOIN initiative i ON i.id = b.initiative_id
GROUP BY i.relationship_id, i.value_type, b.state;

CREATE TABLE value_potential (
  id uuid PRIMARY KEY, relationship_id uuid, lever text, value_type text,
  low numeric, high numeric, certainty text CHECK (certainty IN ('hoch','mittel','niedrig')),
  calc jsonb, supplier_low numeric, supplier_high numeric,
  data_gaps text[], initiative_id uuid, space text NOT NULL DEFAULT 'buyer_private');

CREATE TABLE friction_rate (          -- Kostensätze je Ereignisart, versioniert
  id uuid PRIMARY KEY, org_id uuid, kind text, low numeric, high numeric,
  version int, changed_by uuid, changed_at timestamptz);

CREATE TABLE friction_event (
  id uuid PRIMARY KEY, relationship_id uuid,
  kind text CHECK (kind IN ('eilabruf','abrufaenderung','reklamation','wartezeit')),
  occurred_at timestamptz, source text, est_cost_supplier_low numeric, est_cost_supplier_high numeric,
  rate_version int, space text NOT NULL DEFAULT 'buyer_private');

CREATE TABLE relationship_yield (     -- monatlich, nur Summen
  relationship_id uuid, period date, ebit_secured numeric,
  hours_buyer numeric, hours_supplier_est numeric,
  est_value_supplier_low numeric, est_value_supplier_high numeric,
  PRIMARY KEY (relationship_id, period));
```

## Werkzeuge

`value.find_potentials` (Vorschlagen) · `value.book` (Erledigen, bleibt „in Prüfung“) · `value.prepare_release` (Vorbereiten, erzeugt die Mappe) · `value.release` (Mensch, Token) · `value.confirm` (Controlling, Token) · `rule.freeze_baseline` (Token) · `friction.record` (Erledigen). Rücknahme: Buchung und Reibung in Erledigt; eine Freigabe nur über eine neue Version der Rechenregel mit Begründung.
