# VG-01 Vergabe und Verhandlung der Agenten

Version 1.0 · Kapitel 8 · Pakete K8-d (Vergabe), K8-e (Verhandlung, Lieferantenseite) · baut auf WZ-01, WT-01, ST-01, LP-01, LA-01, AU-01, WK-01 · Bildvorlagen: K8-Vergabe, K8-Verhandlung, K8-Vergabe-Mappe, L8-Angebot · KN-66, KN-67

> **Klärungen aus K0 (24.11.2026, `docs/entscheidungen.md`):** Lead mit Vertretung nach E-K0-07; Beträge in Cent mit Währung (E-K0-10).

## Ziel

Reziproq bereitet eine Vergabe vor, vergleicht die Angebote gegen die Soll-Kosten und verhandelt unverbindlich im Rahmen, den ein Mensch freigegeben hat, Agent gegen Agent. Bindend sind nur das Angebot, das ein Mensch beim Lieferanten bestätigt, und die Vergabe durch den Lead (E-K8-1, einzeln entschieden).

## Grundsätze

- **Getrennt je Bieter:** Jede Anfrage, Rückfrage, Runde und jedes Angebot liegt in der Akte des jeweiligen Lieferanten (`shared` dieser Beziehung). Kein Bieter erfährt Namen, Preise, Bedingungen oder Rang eines anderen, auch nicht in Formulierungen wie „ihr liegt vorn“ oder „zu teuer im Vergleich“. Die Auswertung über alle Angebote liegt in `buyer_private`.
- **Kontext je Akte:** Der Agent bekommt für eine Runde nur die Akte dieses Bieters, den Rahmen und dessen Angebot, nie Angebote anderer Bieter. Der Agent des Lieferanten bekommt nur seine Akte und seine eigene Einstellung (LP-01, LA-01).
- **Der Code setzt die Zahlen:** Gebot und Gegengebot einer Runde berechnet der Code aus Rahmen und Angebot; das Modell formuliert nur und nutzt nur freigegebene Argumente (G-6). Eine Formulierung mit einer Zahl, die nicht in den Fakten der Runde steht, wird nicht gesendet.
- **Kennzeichnung** jeder Runde „Reziproq für <Organisation>“ in beiden Akten gleich (AU-01, G-7).
- Vertrag und Vertragsablage bleiben aus (G-4); Reziproq legt die vereinbarten Eckdaten als PDF bei.

## Ablauf

1. **Vorbereiten** (aus einer Hypothese mit Vergabe oder auf Knopf, Commodity Manager): Bedarf und Mengen aus Teilestamm und Prognose; Lose; Kriterien mit Gewichten (Standard Preis 50, Qualität 25, Kapazität 15, Nachhaltigkeit 10); Pflichtbedingungen; **Shortlist** aus der Supplier Map mit Begründung je Lieferant (Soll-Typ, Bewertung, Kapazität); Lieferanten mit Ausstieg in der Strategie werden nicht angefragt.
2. **Anfragen:** Je Lieferant ein Entwurf in seiner Akte; Senden durch einen Menschen mit Token. Rückfragen beantwortet ein Mensch oder Reziproq als Entwurf, immer nur in der Akte, aus der sie kam.
3. **Angebote:** strukturiert erfasst (Preis je Teil oder Teilefamilie, Kapazität, Bedingungen). Reziproq vergleicht gegen heutigen Preis und gegen Soll (WZ-01) und bewertet nach den Kriterien.
4. **Verhandlung der Agenten** (optional, je Bieter):
   - Voraussetzung: ein vom Menschen freigegebener **Rahmen** (Ziel, freigegebene Argumente, Grenzen wie Mengenzusage und höchstens 3 Runden) und die **Zulassung** durch den Lieferanten in seinen Einstellungen (Standard aus; E-K8-6). Ohne Zulassung geht jede Runde als Entwurf an einen Menschen beim Lieferanten.
   - Runden: Gebot des Käufer-Agenten, Antwort des Lieferanten-Agenten innerhalb der eigenen Untergrenze; höchstens 3 Runden; jede Runde unverbindlich.
   - Ende: Rahmen-Ziel erreicht, Untergrenze erreicht, 3 Runden oder **Stoppen** durch einen Menschen (sofort). Danach bestätigt ein Mensch beim Lieferanten sein Angebot (Token) oder passt es an.
5. **Vergabe-Mappe** für den Lead (`/mappe/vergabe/<id>`): Optionen mit EBIT im Jahr und Abstand zu Soll, Regeln der Strategie geprüft (SZ-01), Rechenweg, Folgen. Vergeben mit Token.
6. **Folgen** (Entwürfe, Weitergabe nach SZ-01): Zuschlag oder Absage je Akte (Absage ohne Informationen über andere Bieter), Initiative auf R3 mit Plan, Baseline zum Starttag, Hypothese bestätigt oder angepasst (WT-01), Prüfpunkte aus der Verhandlung als Zusagen in der Akte.

## Was kein Agent je sagt

Preise, Namen, Bedingungen oder Rang anderer Bieter; Ziel, Mandat oder Soll-Kosten in Zahlen; etwas Bindendes. Ein Prüfschritt im Code vergleicht jede Runde vor dem Senden mit einer Liste verbotener Fakten (Namen anderer Bieter, Zahlen aus Rahmen-Ziel, Mandat und Soll-Kosten) und verwirft sie bei einem Treffer.

## Seiten

**Vergabe (`/warengruppen/<id>/vergaben/<vid>`):** Kopf, Ablauf (Vorbereiten, Anfragen, Angebote, Verhandeln, Vergeben), Als Nächstes, Angebote gegen heute und gegen Soll, Anfragen je Akte, Shortlist, Hypothese dahinter, Regeln „Getrennt je Bieter“ und „Nur für euch“.

**Verhandlung (Blatt):** Stand, Verlauf der Runden mit Kennzeichnung, Rahmen (privat), „Was kein Agent je sagt“, Runde freigeben, Rahmen ändern, Stoppen.

**Lieferantenseite (`/kunden/<id>/anfragen/<vid>`):** Anfrage, eigenes Angebot, Verlauf, Schalter „Verhandlung durch euren Agenten“, Untergrenze und Kalkulation (privat), „Was ihr nie erfahrt“, Angebot bestätigen.

## Daten

```sql
CREATE TABLE sourcing_event (
  id uuid PRIMARY KEY, category_id uuid, hypothesis_id uuid, title text, volume_year numeric,
  starts_on date, criteria jsonb, mandatory jsonb, shortlist jsonb,
  state text CHECK (state IN ('vorbereiten','anfragen','angebote','verhandeln','vergeben','abgeschlossen')),
  owner_person_id uuid, space text NOT NULL DEFAULT 'buyer_private');

CREATE TABLE sourcing_invite (           -- je Bieter, in seiner Akte
  id uuid PRIMARY KEY, sourcing_event_id uuid, relationship_id uuid, body jsonb, due_at date,
  sent_by uuid, sent_at timestamptz, author_kind text, space text NOT NULL DEFAULT 'shared');

CREATE TABLE sourcing_offer (
  id uuid PRIMARY KEY, invite_id uuid, relationship_id uuid, version int, lines jsonb, capacity numeric,
  conditions jsonb, confirmed_by uuid, confirmed_at timestamptz, confirm_token text,
  space text NOT NULL DEFAULT 'shared');

CREATE TABLE sourcing_evaluation (       -- über alle Angebote, nur Käufer
  id uuid PRIMARY KEY, sourcing_event_id uuid, offer_id uuid, vs_today_pct numeric, vs_should_pct numeric,
  scores jsonb, space text NOT NULL DEFAULT 'buyer_private');

CREATE TABLE negotiation_frame (
  id uuid PRIMARY KEY, sourcing_event_id uuid, relationship_id uuid, target jsonb, arguments text[],
  limits jsonb, max_rounds int NOT NULL DEFAULT 3 CHECK (max_rounds <= 3),
  released_by uuid, released_at timestamptz, confirm_token text, stopped_by uuid, stopped_at timestamptz,
  space text NOT NULL DEFAULT 'buyer_private');

CREATE TABLE negotiation_round (         -- in der Akte des Bieters
  id uuid PRIMARY KEY, frame_id uuid, relationship_id uuid, round int, side text CHECK (side IN ('buyer','supplier')),
  proposal jsonb, text text, facts jsonb, author_kind text NOT NULL DEFAULT 'reziproq',
  sent_at timestamptz, space text NOT NULL DEFAULT 'shared');

CREATE TABLE supplier_negotiation_setting (
  relationship_id uuid, sourcing_event_id uuid, allowed boolean NOT NULL DEFAULT false,
  floor jsonb, set_by uuid, space text NOT NULL DEFAULT 'supplier_private',
  PRIMARY KEY (relationship_id, sourcing_event_id));

CREATE TABLE sourcing_award (
  id uuid PRIMARY KEY, sourcing_event_id uuid, option_code text, allocation jsonb, ebit_year numeric,
  gap_to_should_pct numeric, decided_by uuid, decided_at timestamptz, confirm_token text,
  space text NOT NULL DEFAULT 'buyer_private');
```

## Werkzeuge

| Werkzeug | Stufe | Bindend |
|---|---|---|
| `sourcing.prepare` | Vorbereiten | nein |
| `sourcing.send_invites` | nur Mensch | ja, Token |
| `sourcing.compare` | Erledigen (Wert-Engine) | nein |
| `negotiation.frame.release` | nur Mensch | ja, Token |
| `negotiation.round` (Käufer) | Erledigen im Rahmen | nein, unverbindlich |
| `negotiation.round` (Lieferant) | Erledigen innerhalb der Untergrenze, nur mit Zulassung | nein, unverbindlich |
| `negotiation.stop` | jeder Beteiligte | nein |
| `offer.confirm` (Lieferant) | nur Mensch | ja, Token |
| `sourcing.award` | nur Lead | ja, Token |

`negotiation.round` hat `binding_scope = 'keiner'`, steht aber in keiner `channel_policy` (KA-01); `offer.confirm` und `sourcing.award` sind `gegenueber`.

## Fertig, wenn

- [ ] T8-07 Anfragen gehen je Akte einzeln; ein Bieter sieht weder Namen, Preise, Bedingungen noch Rang eines anderen, auch nicht über Agent, Suche oder Frag.
- [ ] T8-08 Eine Verhandlung der Agenten startet nur mit freigegebenem Rahmen und Zulassung durch den Lieferanten; höchstens 3 Runden; Stoppen beendet sie sofort.
- [ ] T8-09 Kein Agent sendet ein bindendes Angebot, einen Zuschlag oder eine Absage; das tun Menschen mit Token.
- [ ] T8-10 Keine gesendete Runde enthält eine Zahl aus Rahmen-Ziel, Mandat oder Soll-Kosten oder den Namen eines anderen Bieters (Prüfschritt mit Testfällen).
- [ ] T8-11 Zahlen der Vergabe-Mappe kommen aus der Wert-Engine (Demo: 110 T€, 3,3 %).
- [ ] T8-12 Nach der Vergabe entstehen Zuschläge und Absagen als Entwürfe je Akte, die Initiative steht auf R3 mit Baseline, die Hypothese ist aktualisiert.
- [ ] T8-VG1 Ohne Zulassung des Lieferanten erscheinen Runden beim Lieferanten nur als Entwurf für einen Menschen.
