# BL-01 Bestätigen per Link

Version 1.0 · Kapitel 2, genutzt in 3 und 4 · Paket K2-d · baut auf ZA-01, ZQ-01, KI-23 · Bildvorlagen: K2-Bestaetigen-Mobil, K3-Beitrag-Mobil

## Ziel

Personen beim Lieferanten (und das Controlling beim Käufer, E-K4-1) bestätigen Zusagen oder liefern Beiträge, ohne ein Konto anzulegen. Der Link zeigt nur, was er nennt.

## Regeln

1. Ein Link gehört zu genau einer Person und nennt genau die Objekte, um die es geht (`commitment_ids`, Beitragsanfragen oder Wertbuchungen).
2. Anmeldung mit Passkey, an die Person gebunden; 14 Tage gültig (E-K2-6). Für Beiträge gilt die Frist des Beitrags.
3. Nach der Nutzung zeigt der Link „bereits bestätigt“ mit Datum; nach Ablauf „abgelaufen“ und den Weg, einen neuen Link anzufordern.
4. Die Seite hat keine Seitenleiste, zeigt Absender, Zweck, die Objekte, „So erscheint es bei <Gegenüber>“ und den Satz „<Gegenüber> sieht nur, was Sie hier senden.“
5. Der Link zeigt nie Daten aus `buyer_private` (beim Lieferanten) und nie Daten anderer Kunden.
6. Abgelehnte Zusagen gehen mit Grund zurück an den Absender (Fokus-Thema).

## Adresse und Daten

`/b/<token>`.

```sql
CREATE TABLE confirm_link (
  token text PRIMARY KEY, relationship_id uuid, person_id uuid,
  commitment_ids uuid[], purpose text DEFAULT 'commitment',   -- commitment | contribution | value_confirmation
  object_ids uuid[], expires_at timestamptz, used_at timestamptz, result text);
```

## Fertig, wenn

- [ ] T2-08 Nach Freigabe ist der Bestätigungslink 14 Tage gültig, zeigt nur die drei Zusagen; eine zweite Nutzung zeigt „bereits bestätigt“.
- [ ] T2-S02 Der Link zeigt nie Daten aus `buyer_private` und nie Daten anderer Kunden.
- [ ] T2-BL1 Ein weitergeleiteter Link ist ohne den Passkey der Person nicht nutzbar.
- [ ] T2-BL2 Bei 390 px ist die Seite ohne waagerechten Bildlauf bedienbar; Knöpfe ≥ 52 px.

## Nicht Teil

Konto und Akte des Lieferanten (LP-01).
