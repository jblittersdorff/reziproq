# IN-07 Import-API

Release I1 · baut auf IN-01, KI-15 · deckt ab IN-08

## Ziel

Die Middleware des Kunden liefert Lieferantenstamm, Spend, Bestellzeilen, Wareneingänge, Gutschriften und Verträge automatisch an Reziproq, ohne Excel. Alles läuft in dasselbe Datenmodell und dieselbe Prüfung wie der Datei-Import (KI-15). Reziproq baut nichts kundenspezifisch.

## Wer darf was

| Rolle | Darf |
|---|---|
| Admin | API-Schlüssel erzeugen, widerrufen und auf Objektarten beschränken; Lieferungen und Fehler sehen; Lieferungen zurücknehmen (wie KI-15). |
| Commodity Manager | Zeilen zur Prüfung entscheiden (wie KI-15). |
| Technischer Zugang (API-Schlüssel) | Nur schreiben in die erlaubten Objektarten, nur lesen von Stand und Fehlern der eigenen Lieferungen. |
| Lieferant | Nie. |

## Daten

| Tabelle | Felder | Art |
|---|---|---|
| `api_key` | `id`, `org_id`, `name`, `prefix`, `hash`, `scopes` (Liste der Objektarten), `created_by`, `created_at`, `last_used_at`, `revoked_at` | `org_private` |
| `import_batch` (KI-15) | neu: `source` (`file`, `api`), `api_key_id`, `idempotency_key` | `org_private` |

Datenmodell (für Datei und API gleich):

| Objektart | Pflichtfelder |
|---|---|
| `supplier` | `external_number`, `name`, `country`, `vat_id` oder `duns`, optional `parent_external_number` |
| `category_map` | `material_group`, `category_key` |
| `spend` | `supplier_external_number`, `period` (YYYY-MM), `amount`, `currency`, `material_group` oder `account`, optional `business_unit` |
| `order_line` | `order_no`, `line_no`, `order_date`, `supplier_external_number`, `material_no`, `quantity`, `unit`, `unit_price`, `currency`, `payment_terms_days`, optional `contract_ref`, `delivery_date` |
| `goods_receipt` | `order_no`, `line_no`, `receipt_date`, `quantity` |
| `credit_note` | `supplier_external_number`, `date`, `amount`, `currency`, optional `reason`, `contract_ref` |
| `contract` | `contract_no`, `supplier_external_number`, `valid_from`, `valid_to`, `kind`, optional `document_url` |
| `quality_notification` | `supplier_external_number`, `material_no`, `date`, `quantity_defective`, `kind` |

Regeln:

- REST mit OpenAPI-Beschreibung unter `/api/v1`. Anmeldung mit `Authorization: Bearer <Schlüssel>`. Der Schlüssel wird einmal angezeigt und nur als Hash gespeichert.
- `POST /api/v1/batches` mit `object_type`, `idempotency_key` und bis zu 10.000 Zeilen je Aufruf.
  - Gleiche `idempotency_key` innerhalb von 24 Stunden ergibt dieselbe Antwort ohne neue Verarbeitung.
  - Größere Mengen: mehrere Aufrufe mit `batch_id` und `final: true` am Ende.
- Antwort sofort mit `batch_id` und Stand `processing`. Verarbeitung im Job nach KI-15: Zuordnung, Prüfwarteschlange, Übernahme.
- `GET /api/v1/batches/<id>` liefert Stand, Zahl der Zeilen je Status und Fehler je Zeile (Zeilennummer, Feld, Grund). Keine Inhalte anderer Lieferungen.
- Für Lieferungen über die API ist **Übernehmen** automatisch, wenn keine Zeile zur Prüfung offen ist. Sonst warten nur die offenen Zeilen auf Prüfung, der Rest wird übernommen.
- Spend und Bestellzeilen derselben Periode und Herkunft ersetzen die vorige Lieferung (Ersetzen je Periode). Andere Objektarten werden über ihre Schlüssel aktualisiert.
- Ratenbegrenzung: 60 Aufrufe je Minute und Schlüssel. Antwort 429 mit `Retry-After`.
- Alle Beträge als Dezimalzahl mit Punkt, Datumswerte nach ISO 8601. Felder außerhalb des Modells werden ignoriert und gemeldet.

## Ablauf

1. **Einstellungen › Anbindungen › Import-API:** Schlüssel erzeugen mit Name und Objektarten. Liste der Schlüssel mit letzter Nutzung, **Widerrufen**. Link zur API-Beschreibung.
2. **Lieferungen:** dieselbe Liste wie im Import (KI-15), Quelle „API“, mit Stand und Fehlern. Die Prüfwarteschlange ist dieselbe Seite wie beim Datei-Import.
3. Die Anbindungsseite (IN-01) zeigt die letzte Lieferung und offene Fehler. Bei Fehlern steht die Tinte-Karte dort.

## Fertig, wenn

Je Kriterium ein Test.

- [ ] Eine Lieferung mit gültigem Schlüssel und 100 Zeilen Spend wird übernommen. Die Summe stimmt auf den Cent.
- [ ] Eine Wiederholung mit gleicher `idempotency_key` verarbeitet nichts neu und liefert dieselbe Antwort.
- [ ] Ein Schlüssel ohne die Objektart `order_line` kann keine Bestellzeilen liefern.
- [ ] Ein widerrufener Schlüssel wird mit 401 abgelehnt.
- [ ] Eine Zeile mit falschem Datum erscheint als Fehler mit Zeilennummer und Feld. Die anderen Zeilen werden verarbeitet.
- [ ] Spend derselben Periode ersetzt die vorige Lieferung, statt sie zu verdoppeln.
- [ ] Zeilen zur Prüfung blockieren die Übernahme der übrigen Zeilen nicht.
- [ ] Über 60 Aufrufe je Minute ergeben 429.
- [ ] Kunde A kann mit seinem Schlüssel keine Lieferung von Kunde B lesen.
