# KI-09 Eigene Agenten

> **Status 24.11.2026 (Umbau KI-nativ): zurückgestellt.** Maßgeblich: –. Eigene Agenten der Kunden (KN-54) werden nicht umgesetzt. Kein Code, keine Tabellen, keine Seite. Bei Widerspruch gelten `docs/entscheidungen.md` und die genannten Specs; Begriffe nach NAV-10 (Heute, Beziehungen, Wert, Mein Agent, Verlauf, Zusage).

Release K3 · baut auf KI-04 · deckt ab KI-09, KI-10

## Ziel

Käufer legen eigene Agenten an, ohne Code: Aufgabe in eigenen Worten, Daten, Auslöser, Ergebnis, Prüfer. Ein Testlauf mit echten Daten zeigt vorher, was herauskommt und was es kostet.

## Wer darf was

| Rolle | Darf |
|---|---|
| Rollen aus `ai_custom_agent_roles` (Start: alle Käufer mit Zugriff auf mindestens eine Beziehung) | Eigene Agenten anlegen, testen, ändern, pausieren, löschen. |
| Admin | Agenten freigeben oder mit Kommentar zurückgeben, jeden eigenen Agenten pausieren. |
| Käufer: alle mit Zugriff | Aktive eigene Agenten anderer sehen und von Hand starten, wenn sie die Daten sehen dürfen. |
| Lieferant | Nie. |

## Daten

Keine neuen Tabellen. Eigene Agenten sind Einträge in `agent` mit `kind` = `custom` und Versionen in `agent_version` (KI-04).

Auswahl beim Anlegen:

| Feld | Auswahl |
|---|---|
| Aufgabe | Freitext, höchstens 2.000 Zeichen |
| Daten | Werkzeuge aus der Registry, nur Datenbereiche, die der Nutzer sehen darf |
| Auslöser | Von Hand · Zeitplan (wöchentlich oder monatlich, Tag und Uhrzeit) · Ereignis aus fester Liste: Feedback aufgedeckt, Zusage überfällig, QBR in 7 Tagen, Spend-Import fertig |
| Umfang | Meine Fokuslieferanten · ein Lieferant · eine Warengruppe |
| Ergebnis | Aufgabe für mich · Entwurf einer internen Maßnahme (QBR-03) · Notiz |
| Prüfer | Ich · SRO der jeweiligen Beziehung |
| Budget je Lauf | höchstens der Wert aus KI-01 |

- Agenten bewerten Lieferanten und Beziehungen, nie einzelne Personen. Beim Speichern prüft ein Modell der Klasse `small` die Aufgabe. Verlangt sie eine Bewertung von Personen, wird gespeichert, aber nicht aktiviert, mit dem Hinweis, was zu ändern ist. Kein Werkzeug liefert Leistungsdaten einzelner Personen.
- Aktivieren setzt einen erfolgreichen Testlauf der aktuellen Version voraus.
- Freigabe durch Admin ist nötig, wenn `ai_custom_agent_approval` an ist und der Agent einen Zeitplan, ein Ereignis oder ein Werkzeug nach außen nutzt.
- Jede Änderung erzeugt eine neue Version. Läufe verweisen auf die Version, mit der sie liefen.
- Ein eigener Agent handelt immer im Namen seines Besitzers. Verliert der Besitzer den Zugriff, pausiert der Agent.

## Ablauf

1. **Agent anlegen** (`/agenten/neu`): Start aus „Leer“, aus einer Vorlage (Agent von Reziproq duplizieren) oder aus einer Frage auf der Seite „Fragen“ (**Als Agent anlegen** übernimmt die Frage als Aufgabe).
2. Fünf nummerierte Abschnitte: Was soll der Agent tun · Welche Daten darf er lesen · Wann läuft er · Was kommt heraus · Wer prüft und was darf es kosten.
3. Rechts **Testlauf**: läuft mit echten Daten als `is_test`, zeigt das Ergebnis als Entwurfskarte, Schritte und Kosten. Er legt keine Entwürfe an.
4. Nach bestandenem Testlauf: **Agent aktivieren** oder, wenn Freigabe nötig ist, **Zur Freigabe senden**. Der Admin bekommt eine Aufgabe und sieht den Agenten auf der Seite Einstellungen KI (KI-01).
5. **Freigeben** setzt den Stand auf aktiv. **Zurückgeben** verlangt einen Kommentar.
6. Auf der Seite des Agenten: **Pausieren**, **Bearbeiten** (neue Version, neuer Testlauf), **Löschen**. Läufe und Entwürfe bleiben nach dem Löschen erhalten.

## Fertig, wenn

Je Kriterium ein Test.

- [ ] Ein Agent ohne erfolgreichen Testlauf der aktuellen Version lässt sich nicht aktivieren.
- [ ] Die Werkzeugauswahl zeigt nur Datenbereiche, die der Nutzer sehen darf.
- [ ] Ein Agent mit Zeitplan geht bei eingeschalteter Freigabe an den Admin und läuft erst nach der Freigabe.
- [ ] Die Aufgabe „Bewerte, welcher Einkäufer seine Lieferanten am schlechtesten betreut“ wird nicht aktiviert und nennt den Grund.
- [ ] Verliert der Besitzer den Zugriff auf eine Beziehung, liefert der Agent für sie keine Daten mehr. Verliert er jeden Zugriff, pausiert der Agent.
- [ ] Eine Änderung erzeugt Version 2. Frühere Läufe zeigen weiter Version 1.
- [ ] Ein eigener Agent von Kunde A ist für Kunde B unsichtbar.
- [ ] Der Test-Lieferant sieht keinen eigenen Agenten.

## Nicht Teil dieser Funktion

- Eigene Werkzeuge und Code
- Anbindung eigener MCP-Server
- Agenten, die direkt etwas ändern oder an Lieferanten senden
