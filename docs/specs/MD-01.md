# MD-01 Mandat

Version 1.0 · Kapitel 2, erweitert in 5 und 6 · Pakete K2-g, K5-d, K6-d · baut auf MA-01, Lieferantenplan, Spielregeln · Bildvorlagen: K2-Mandat, K5-Deal-Mappe (Prüfung), K6-Mandat

> **Klärungen aus K0 (24.11.2026, `docs/entscheidungen.md`):** „Lead der Beziehung“ ist der Lead der Haupt-Warengruppe, mit Vertretung (E-K0-07); „strategisch“ heißt Fokuslieferant (E-K0-09).

## Ziel

Ein Mandat ist der Rahmen je Beziehung: Ziel, Grenzen und was Reziproq hier selbst tut. Reziproq prüft Deals und Antworten dagegen und sagt vor einer Zusage, wenn etwas außerhalb liegt. Das Mandat sieht nur die Käuferseite.

## Pflicht

Pflicht für strategische Beziehungen, sonst freiwillig (E-K2-4). Ohne bestätigtes Mandat bietet Reziproq bei einer strategischen Beziehung keinen Deal-Antwortentwurf an, sondern ein Fokus-Thema „Mandat bestätigen“.

## Inhalt

| Teil | Beispiel Rheintal |
|---|---|
| Ziel | Kapazität 2028 sichern · Stückpreis −3 % bis Ende 2027 · Reklamationen 42 → 20 ppm |
| Grenzen | Preis: Zielkorridor −1,5 bis −3 %, Nachlass nur gegen Gegenleistung · Prognose: bis 12 Monate teilen, verbindlich höchstens 3 Monate · Laufzeit: Rahmenvertrag höchstens 3 Jahre |
| Nie ohne Lead | Volumengarantie über 70 % des Bedarfs, Exklusivität |
| Was Reziproq hier selbst tut | je Aufgabe eine Stufe, höchstens die aus Mein Agent („wie in Mein Agent“ als Standard) |
| Herkunft | Lieferantenplan (Version), Spielregeln, Strategie (Version, ab Kapitel 6), Mein Agent |

## Ablauf

1. Reziproq leitet das Mandat aus Lieferantenplan und Spielregeln ab (Entwurf, Fokus „Mandat bestätigen“).
2. Ein Mensch bestätigt oder passt an (bindend, Token). Erst dann gilt es.
3. Bei jedem Deal-Vorschlag und jedem Antwortentwurf prüft Reziproq jede Grenze (DL-01): im Mandat, außerhalb mit Abstand („+3 Monate“), nicht geregelt. Einen Antwortentwurf, der eine Grenze überschreitet, bereitet Reziproq nicht vor; die Mappe nennt Grenze und Abstand.
4. Außerhalb des Mandats darf nur der Lead der Beziehung annehmen, oder seine Vertretung (E-K5-2).
5. Ab Kapitel 6 entstehen Änderungen auch aus einer freigegebenen Strategie (MV-01). Jede Änderung ist eine neue Version; Deals verweisen auf die Version, gegen die sie geprüft wurden.

## Daten

```sql
CREATE TABLE mandate (
  relationship_id uuid PRIMARY KEY, goals jsonb, limits jsonb,
  autonomy_caps jsonb,              -- je Aufgabe höchstens die Stufe aus worker_setting
  source_plan_version int, derived_at timestamptz,
  confirmed_by uuid, confirmed_at timestamptz,
  current_version int NOT NULL DEFAULT 1,
  space text NOT NULL DEFAULT 'buyer_private');
-- mandate_version (Historie) siehe MV-01
```

`limits` ist eine Liste von Grenzen mit `key`, `kind` (`range`, `max`, `never_without`), Werten und Einheit, damit die Prüfung im Code läuft (G-6).

## Seite `/beziehungen/<id>/mandat`

Kopf „Mandat für <Lieferant>“, Unterzeile „nur für euch“; Als Nächstes (bestätigen oder Vorschlag prüfen); Ziel und Grenzen mit Schloss „<Lieferant> sieht es nie“; „Was Reziproq hier selbst tut“ mit Stufen-Umschaltern (Obergrenze Mein Agent); Herkunft; „Was ein Mandat bewirkt“.
