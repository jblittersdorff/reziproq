# FS-01 Hinweise

Release 1.0 · baut auf allen Modulen bis 0.3 · deckt ab FS-01, FS-02

## Ziel

Reziproq warnt vor den typischen Fehlern im Lieferantenmanagement. Jeder Hinweis führt dorthin, wo man ihn behebt, und lässt sich annehmen oder begründet verwerfen.

## Wer darf was

| Rolle | Darf |
|---|---|
| SRO der Beziehung, Admin | Hinweise annehmen (erzeugt eine interne Maßnahme) oder mit Begründung verwerfen. |
| Käufer: alle mit Zugriff | Hinweise sehen. |
| Admin | Schwellwerte der Regeln einstellen. |
| Lieferant | Nie. |

## Daten

| Tabelle | Felder | Art |
|---|---|---|
| `hint` | `id`, `org_id`, `relationship_id` (optional), `rule_key`, `fingerprint`, `status` (`open`, `accepted`, `dismissed`), `reason`, `created_at`, `decided_by`, `decided_at` | `org_private` |

- Ein täglicher Job prüft alle Regeln.
- Der `fingerprint` beschreibt die Lage, die den Hinweis auslöst. Ein verworfener Hinweis kommt nur wieder, wenn sich die Lage ändert.
- Angenommen heißt: Es entsteht eine interne Maßnahme (QBR-03) mit privater Quelle Hinweis.

**Regeln:**

| Regel | Auslöser |
|---|---|
| Segment nur aus Spend | Konsolidierter Typ, ohne dass ein anderes Kriterium bewertet ist |
| Großlieferant automatisch Fokus | Fokus mit Begründung kürzer als 20 Zeichen oder nur „Spend“ |
| Ungeklärte Abweichung | wie in SEG-07 definiert |
| Zu viele Fokuslieferanten je SRO | über einem einstellbaren Wert |
| Keine operative Funktion im Team | nur Einkauf im Team |
| Takt verfehlt | vereinbartes Format seit mehr als seinem Takt ohne Termin |
| Kein Feedback | seit zwölf Monaten keine aufgedeckte Welle |
| Lieferantenplan fehlt | zwei Wochen vor dem Joint Business Planning nicht freigegeben |
| Recht ohne Pflicht | in freigegebenen Spielregeln |
| Zusagen des Käufers überfällig | mindestens eine |

## Ablauf

1. **Hinweise** (`/hinweise`): Liste nach Lieferant gruppiert, je Hinweis ein Satz, warum, und der Knopf **Beheben**. Er führt zum Ort.
2. **Annehmen** und **Verwerfen** stehen auf der Hinweis-Seite `/hinweise/<id>`. Verwerfen verlangt eine Begründung.
3. Start (NAV-05) und der Überblick des Lieferanten (NAV-06) zeigen die Anzahl offener Hinweise.

## Fertig, wenn

Je Kriterium ein Test.

- [ ] Jede Regel löst mit Testdaten genau einen Hinweis aus.
- [ ] Ein verworfener Hinweis kommt nicht wieder, solange sich die Lage nicht ändert. Die Begründung steht im Verlauf.
- [ ] Annehmen erzeugt eine interne Maßnahme ohne Fremdschlüssel von geteilt auf privat.
- [ ] Der Test-Lieferant sieht keine Hinweise.

## Nicht Teil dieser Funktion

- Hinweise per Mail
- Regeln auf Daten aus SAP oder Coupa
