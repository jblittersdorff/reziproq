# DL-01 Deal und Mandat-Prüfung

Version 1.0 · Kapitel 5 · Pakete K5-c, K5-d · baut auf ZA-01, MD-01, WK-01, PR-01, AU-01 · ersetzt KI-20 Szenarien, KI-21 Verhandlungsvorbereitung · Bildvorlagen: K5-Deal-Mappe, K5-Szenarien, K5-Deal, L5-Deal-Mappe, L5-Bestaetigen-Mobil · KN-19, KN-35, KN-36

## Ziel

Ein Deal ist eine Vereinbarung zwischen beiden Seiten in derselben Akte: Vorschlag, Antwort, Bestätigung. Reziproq prüft jeden Vorschlag gegen das Mandat, rechnet den Wert für beide Seiten mit der Wert-Engine und bereitet die Antwort vor. Senden und Bestätigen tut ein Mensch.

## Grundsätze

- Der Deal und seine Fassungen liegen in `shared`. Mandat-Prüfung und Bewertung liegen je Seite privat (`buyer_private` bzw. `supplier_private`).
- Der Wert des Gegenübers ist immer eine Schätzung, erscheint nur auf der eigenen privaten Seite und immer als „≈“ mit Spanne (G-3, G-6).
- Jede Nachricht in der Mitte trägt eine Kennzeichnung (AU-01).
- Ein Deal gehört zu genau einer Akte. Kein Serienversand; Vorlagen beim Lieferanten nur nach LA-01 (E-K5-5).
- Den Vertragsnachtrag schreibt die Rechtsabteilung; Reziproq legt die vereinbarten Punkte als PDF bei. Das Vertragsmodul bleibt aus (G-4).

## Ablauf

1. **Vorschlag.** Eine Seite schlägt vor (in der Demo Rheintal, Do 10.12., 08:40; L5-Deal-Mappe). Eine Fassung hat Bedingungen je Seite, einen Grund und optional die Kostenspanne des Lieferanten (LA-01).
2. **Prüfung gegen das Mandat** (Käuferseite, automatisch, Erledigen, innerhalb einer Minute): je Grenze aus `mandate.limits` ein Ergebnis `im_mandat`, `ausserhalb` mit Abstand („+3 Monate“) oder `nicht_geregelt`. Die Prüfung verweist auf die Mandatsversion (MV-01).
3. **Bewertung je Seite** (Erledigen, Wert-Engine): Optionen mit Wert für die eigene Seite und Schätzung für das Gegenüber. Ohne geteilte Spanne rechnet die Engine mit Branchenwerten und sagt das; mit Spanne mit der Zahl des Lieferanten.
4. **Mappe** „<Lieferant> Deal entscheiden“ (`/mappe/deal/<id>`) in Heute (Fokus), mit fünf Teilen: worum es geht (Spiegel), Vorschlag (geteilt, gekennzeichnet), Mandat-Prüfung (privat), Optionen A bis D mit Wert für beide, Empfehlung und dein Schritt. Rechts: „Was <Gegenüber> sieht“ und „Nie“.
5. **Antwort.** Optionen: Annehmen, Annehmen mit Bedingung, Gegenvorschlag, Ablehnen. Reziproq entwirft die Antwort (Vorbereiten). Eine Option außerhalb des Mandats steht nur als „nur mit <Lead>“ da; Reziproq bereitet dafür keinen Entwurf vor und lässt sie nur den Lead der Beziehung oder seine Vertretung senden (E-K5-2, MD-01).
6. **Bestätigung** durch die andere Seite (beim Lieferanten Mappe `/mappe/deal/<id>` in seiner Navigation) (Web oder mobil: Bestätigen, Gegenvorschlag, Anrufen). Bestätigen ist bindend. Danach `status = gilt`.
7. **Folgen** (automatisch, in Erledigt zurücknehmbar): je Bedingung eine Zusage mit Person und Frist (ZQ-01); Initiative auf R3 (WK-01); Entwurf der laufenden Planversion um die Initiative ergänzt (GP-01); Rechenregel mit Baseline, die am Tag vor dem Start eingefroren wird.

## Deal als Objekt (`/beziehungen/<id>/deals/<deal>`, beim Lieferanten `/kunden/<id>/deals/<deal>`)

Kopf mit Status und „von beiden Seiten bestätigt“, Eckdaten als PDF; Vereinbartes (geteilt, „<Gegenüber> sieht dasselbe“); Verlauf mit Kennzeichnung; Zusagen aus dem Deal; Hinweis zum Vertragsnachtrag; rechts „Nur für euch“: Wert, Schätzung für das Gegenüber, Mandat-Stand, Initiative mit Reife, Baseline, Verweis auf den Gemeinsamen Plan.

## Varianten rechnen (Blatt über der Mappe)

Regler je Bedingung (in der Demo: Nachlass 1,5 / 1,8 / 2,0 %, verbindliche Monate 3 / 6, Laminatvorschau 6 Monate / keine). Die Wert-Engine rechnet je Variante; Reziproq erklärt in einem Satz. Darunter alle Varianten mit Mandat-Status und „im Plus / kann ins Minus / meist im Minus“ für das Gegenüber. Probeverhandlung mit dem Simulator (SI-01) und Gesprächsleitfaden. Das Blatt ist keine Seite (G-8).

## Daten

```sql
CREATE TABLE deal (
  id uuid PRIMARY KEY, relationship_id uuid NOT NULL, title text,
  status text NOT NULL CHECK (status IN ('vorgeschlagen','beantwortet','gilt','abgelehnt','zurueckgezogen')),
  initiative_id uuid, proposed_by_side text CHECK (proposed_by_side IN ('buyer','supplier')),
  answer_due date, valid_from timestamptz, space text NOT NULL DEFAULT 'shared');

CREATE TABLE deal_offer (               -- jede Fassung, nie überschrieben
  id uuid PRIMARY KEY, deal_id uuid, version int, side text,
  kind text CHECK (kind IN ('vorschlag','annahme_mit_bedingung','gegenvorschlag','bestaetigung','ablehnung')),
  terms jsonb,                          -- je Bedingung: Seite, Text, Wert, Einheit, ab
  reason text, cost_range_id uuid, sent_by uuid, sent_at timestamptz,
  author_kind text CHECK (author_kind IN ('mensch','mit_reziproq','reziproq')),
  confirm_token text, space text NOT NULL DEFAULT 'shared');

CREATE TABLE deal_message (
  id uuid PRIMARY KEY, deal_id uuid, author_person_id uuid,
  author_kind text CHECK (author_kind IN ('mensch','mit_reziproq','reziproq')),
  body text, created_at timestamptz, space text NOT NULL DEFAULT 'shared');

CREATE TABLE mandate_check (            -- Käuferseite
  id uuid PRIMARY KEY, deal_offer_id uuid, mandate_id uuid, mandate_version int,
  results jsonb,                        -- je Grenze: key, Status, Abstand
  checked_at timestamptz, space text NOT NULL DEFAULT 'buyer_private');

CREATE TABLE deal_valuation (           -- je Seite, nie shared
  id uuid PRIMARY KEY, deal_offer_id uuid, side text, option_code text, terms jsonb,
  own_value numeric, own_value_type text, counterpart_low numeric, counterpart_high numeric,
  basis text CHECK (basis IN ('branchenwerte','spanne','spanne_zurueckgezogen')),
  calc jsonb, space text NOT NULL CHECK (space IN ('buyer_private','supplier_private')));
```

`cost_range` siehe LA-01. Die Regel „nie shared“ für `deal_valuation` steht als CHECK in der Tabelle und als Test.
