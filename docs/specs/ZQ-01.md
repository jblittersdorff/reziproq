# ZQ-01 Zusagen und Zusagequote

Version 1.0 · Kapitel 2 · Pakete K2-a, K2-b · baut auf ZA-01 · ersetzt Maßnahmen (geteilt → Zusage, intern → Aufgabe; E-K2-1) · Bildvorlagen: L-Ueberblick (Zusagen), K2-Mail-Zusage, Termin-Ergebnisse, K2-Bestaetigen-Mobil

## Ziel

Beide Seiten machen Zusagen mit Frist und Messung. Gehaltene Zusagen ergeben eine Quote je Seite, die beide gleich sehen. Sie ist die Grundlage des Spiegels.

## Daten

```sql
ALTER TABLE commitment
  ADD COLUMN side            text NOT NULL CHECK (side IN ('buyer','supplier')),
  ADD COLUMN kind            text NOT NULL DEFAULT 'zusage' CHECK (kind IN ('zusage','massnahme')),  -- 'massnahme' nur für Altbestand
  ADD COLUMN owner_person_id uuid,
  ADD COLUMN measure         text,          -- woran Erfüllung gemessen wird
  ADD COLUMN source_type     text,          -- mail | termin | feedback | hinweis | hand | deal
  ADD COLUMN source_ref      uuid,
  ADD COLUMN source_span     int4range,     -- Textstelle in der Mail
  ADD COLUMN supersedes_id   uuid REFERENCES commitment(id),
  ADD COLUMN condition_id    uuid REFERENCES commitment(id),
  ADD COLUMN status          text NOT NULL DEFAULT 'offen'
             CHECK (status IN ('offen','gehalten','verfehlt','ersetzt','zurueckgezogen')),
  ADD COLUMN fulfilled_evidence jsonb;      -- Beleg der Buchung „gehalten“

CREATE TABLE task (                         -- interne Aufgaben, früher interne Maßnahmen
  id uuid PRIMARY KEY, relationship_id uuid, title text, owner_person_id uuid,
  due_date date, status text, origin text, space text NOT NULL DEFAULT 'buyer_private');

CREATE VIEW commitment_rate AS              -- je Beziehung, Seite, Jahr
SELECT relationship_id, side, date_part('year', due_date) AS year,
       count(*) FILTER (WHERE status = 'gehalten') AS kept,
       count(*) FILTER (WHERE status IN ('gehalten','verfehlt')) AS due
FROM commitment
WHERE confirm_state = 'both_confirmed'
GROUP BY relationship_id, side, date_part('year', due_date);
```

Migration: geteilte Maßnahmen → `commitment` mit `kind = 'zusage'`; interne → `task`.

## Regeln

1. **Entstehung.** Zusagen entstehen als Entwurf von Reziproq aus Mail (PO-01), Termin (PR-01), Feedback, Hinweis oder Deal (DL-01), oder von Hand („Neue Zusage“ in der Akte). Eine Zusage im Namen des Käufers ist bindend und braucht Token; eine Zusage des Lieferanten gilt nach dessen Bestätigung (BL-01 oder LP-01).
2. **Quote.** Nur `both_confirmed` zählt (ZA-01). Gehalten nur mit Beleg (`fulfilled_evidence`: Lieferavis, Wareneingang, Dokument, Bestätigung der anderen Seite). Quote = gehalten / fällig im Jahr.
3. **Ersatz.** Wird eine Zusage ersetzt, zählt die alte als verfehlt nur, wenn ihre Frist vor dem Ersatz verstrichen war (E-K2-2).
4. **Sichtbarkeit.** Beide Seiten sehen beide Quoten ihrer Beziehung, nie einen Vergleich mit anderen Lieferanten (E-K2-3).
5. **Nachhalten.** Die Aufgabe „Zusagen nachhalten“ prüft fällige Zusagen täglich, bucht mit Beleg als gehalten (Erledigen, rücknehmbar) und erinnert den Lieferanten an seine Zusagen, gekennzeichnet als Nachricht von Reziproq (E-K1-5). An Zusagen des Käufers erinnert sie intern.
6. **Herkunft** wird an der Zusage gezeigt („Termin 04.12.“, „aus Mail vom …“, „aus Deal …“).

## Oberfläche

Zusagen-Zeile: Monogramm der Seite (eigene Seite Tinte, Gegenüber Petrol), Titel, Seite · Person · Frist · Herkunft, Status-Chip (offen, Entwurf, überfällig, Rheintal bestätigt noch, gehalten). Mini-Spiegel 200 px in Listen, Spiegel in der Akte (Designsprache).
