# KI-07 Agent QBR-Vorbereitung

Release K1 · baut auf KI-04 · deckt ab KI-07

## Ziel

Sieben Tage vor jedem Quarterly Business Review liest der Agent alles Relevante zur Beziehung und entwirft Themen, Risiken und offene Punkte. Der SRO geht vorbereitet ins Gespräch, ohne Daten zusammenzusuchen.

## Wer darf was

| Rolle | Darf |
|---|---|
| SRO der Beziehung | Lauf starten, Entwürfe übernehmen. Der Lauf handelt in seinem Namen. |
| Käufer mit Zugriff auf die Beziehung | Lauf und Entwürfe sehen. |
| Lieferant | Nie, auch nicht die übernommenen Inhalte, solange sie nicht ausdrücklich in die geteilte Agenda übernommen sind. |

## Daten

Keine neuen Tabellen. Der Agent ist ein Eintrag in `agent` mit `kind` = `system` und `key` = `qbr_prep`.

| Einstellung | Wert |
|---|---|
| Auslöser | Zeitplan: 7 Tage vor jedem Termin vom Typ QBR. Von Hand auf der Seite des Termins. |
| Handelt im Namen von | SRO der Beziehung |
| Werkzeuge | Kennzahlen der Scorecard, Zusagen, Maßnahmen, Feedback-Aggregate, Notizen der letzten zwei Termine, Wirkung der Initiativen |
| Modell | `standard`, Zusammenfassung `synthesis` |
| Budget je Lauf | 1,50 €, höchstens 30 Schritte |
| Ergebnis | Entwürfe auf der Seite des Termins |

Ergebnis, je als Entwurf (KI-03):

| Teil | Inhalt | Zielort |
|---|---|---|
| Themen | Drei bis fünf Themen mit Begründung | interne Vorbereitung des Termins |
| Risiken | Kennzahlen hinter Plan, überfällige Zusagen, Feedback-Lücken | interne Notiz zum Termin |
| Offene Punkte | Zusagen beider Seiten mit Fälligkeit bis zum Termin | interne Vorbereitung des Termins |

- Zahlen rechnet der Code in SQL. Das Modell erklärt und formuliert.
- Jede Aussage verweist auf das Objekt, aus dem sie stammt.
- Es entsteht nur die interne Fassung. Eine geteilte Fassung für beide Seiten ist ein eigener Agent und nicht Teil dieser Spec.
- Gibt es für diese Beziehung bereits einen offenen Entwurf aus einem früheren Lauf, wird er ersetzt und der alte verworfen mit Grund „neuer Lauf“.

## Ablauf

1. Ein täglicher Job prüft Termine vom Typ QBR in sieben Tagen und startet je Termin einen Lauf.
2. Der SRO bekommt eine Aufgabe „QBR vorbereiten: Entwürfe prüfen“. Mein Tag (NAV-10) zeigt sie.
3. Die Seite des Termins zeigt die Entwürfe in der internen Vorbereitung und einen Verweis auf das Laufprotokoll.
4. **Neu vorbereiten** auf der Seite des Termins startet einen Lauf von Hand.
5. Um ein Thema in die geteilte Agenda zu bringen, übernimmt der SRO es zuerst und fügt es dann ausdrücklich der Agenda hinzu.

## Fertig, wenn

Je Kriterium ein Test.

- [x] Für einen Termin vom Typ QBR in sieben Tagen entsteht genau ein Lauf und eine Aufgabe für den SRO.
- [x] Mit Testdaten entstehen Entwürfe für Themen, Risiken und offene Punkte, jede Aussage mit Quelle.
- [x] Eine Kennzahl hinter Plan erscheint als Risiko mit dem Wert aus der Datenbank, nicht mit einem vom Modell erzeugten.
- [x] Ein zweiter Lauf ersetzt den offenen Entwurf des ersten.
- [x] Der Test-Lieferant sieht weder Lauf noch Entwürfe noch übernommene interne Inhalte.

## Umsetzung (Stand 23.11.2026, Schritt 10 der Warteschlange)

- Entscheidung F6 (23.11.2026): nur QBR sieben Tage vorher; ein neuer Lauf ersetzt nur die offenen
  Entwürfe desselben Termins (Grund „neuer Lauf“), nicht alle der Beziehung.
- Täglicher Job (pg-boss, 5 Uhr) je Käufer: QBR mit Stand „geplant“ in sieben Tagen, Agent
  eingeschaltet, SRO vorhanden. Genau ein Zeitplan-Lauf je Termin und eine interne Maßnahme
  „QBR vorbereiten: Entwürfe prüfen“ für den SRO, die Mein Tag zeigt.
- Der bestehende Lauf (KI-04) schreibt weiter die Zusammenfassung für den Pre-Read und legt dazu drei
  Entwürfe an (`ai_draft` Arten `qbr_topics`, `qbr_risks`, `qbr_open_points`, Migration 0105), jede
  Aussage mit Quelle (Kennzahl, Zusage, Feedback-Ergebnis, Wertpotenzial).
- Zahlen und Sätze kommen aus dem Code (SQL); das Modell schreibt nur die Zusammenfassung.
  „Hinter Plan“ heißt: Fortschritt von der Basis zum Ziel liegt mehr als zehn Punkte hinter der
  verstrichenen Zeit seit Anlage der Kennzahl; ohne Basis zählt ein verfehltes Ziel nach Ablauf.
- Termin-Seite (nur Käufer): Bereich „Interne Vorbereitung von Reziproq“ mit Übernehmen,
  Verwerfen, „Neu vorbereiten“; ein übernommenes Thema geht über „In die Agenda“ nur mit seinem
  Titel in die geteilte Agenda.
- Offen: Verweis auf das Laufprotokoll von der Termin-Seite (das Protokoll liegt unter Einstellungen,
  KI); Modell `synthesis` für die Zusammenfassung (heute `standard` wie in KI-04).
