# TE-01 Termin

Version 1.0 · Kapitel 3 · Pakete K3-a, K3-b · baut auf ZA-01, AK-01, KI-07 · ersetzt Termin-Seiten mit Reitern, J-Anfordern, J-Beitraege, P-Vorbereitung · Bildvorlagen: Termin-Briefing, J-Moderation, Termin-Ergebnisse, A-JBP, K7-Kalender

## Ziel

Ein Termin ist ein Objekt mit drei Phasen. Die Seite zeigt immer die Phase, die gerade dran ist: vorher die Vorbereitung, währenddessen die Moderation, danach die Ergebnisse.

## Seite `/termine/<id>`

**Kopf:** „‹ <Beziehung>“, Datumskreis (56 px, Tinte mit Mint), Titel, graue Zeile (Datum, Uhrzeit, Ort oder Online, Teilnehmende, Termintyp, Herkunft „aus Outlook über das Add-in“), Aktionen (Frag zum Termin, Präsentation starten), Phasen-Umschalter mit Schrittkreisen: 1 Vorbereiten · 2 Im Termin · 3 Danach.

**Phase** wird nicht gespeichert, sondern mit der Uhr je Mandant berechnet: Vorbereiten, solange jetzt < Beginn; Im Termin bis Ende + 15 Minuten; sonst Danach. Der Umschalter erlaubt den Blick in jede Phase.

**Vorbereiten** (KI-07, Briefing-Worker auf Vorbereiten): Als Nächstes (z. B. „Agenda prüfen und an Rheintal senden“); Ziele (privat, je Ziel „erreicht, wenn …“ und Wertbezug, z. B. „Ziel 1 · Prognose gegen Preis und Lieferzeit · 63 T€ EBIT“; E-K3-1); Agenda (geteilt nach Freigabe) mit Uhrzeit, Thema, wer führt, Beiträge je Seite mit Status; Beiträge (BE-01); offene Fragen und Antwortvorschläge (privat); Deck (DK-01); Teilnehmende. Vorlauf für JBP 10 Tage (E-K3-4); ändern sich Eingaben, erscheint „Neu vorbereiten“.

**Im Termin** und **Danach**: PR-01.

## Termine in Heute und Akte

`timeline_item` bleibt die Quelle für Termine in Heute („Diese Woche“), in der Akte („Nächste Wochen“) und im Kalender (KA-01). Neue `kind`-Werte: `agenda_due`, `contributions_due`. Zeilen öffnen den Termin in der passenden Phase.

## Daten

```sql
ALTER TABLE meeting
  ADD COLUMN agenda_shared_at timestamptz,
  ADD COLUMN contributions_due timestamptz,
  ADD COLUMN transcript_enabled boolean DEFAULT false;

CREATE TABLE meeting_goal (            -- privat
  id uuid PRIMARY KEY, meeting_id uuid, title text, achieved_when text,
  value_ref uuid, origin text, space text NOT NULL DEFAULT 'buyer_private');

CREATE TABLE agenda_item (
  id uuid PRIMARY KEY, meeting_id uuid, position int, starts_at time, minutes int,
  title text, lead_person_ids uuid[], goal_id uuid, topic_ref uuid,
  space text NOT NULL DEFAULT 'shared', confirm_state text);
```

`agenda_item.goal_id` verweist auf ein privates Ziel; die Lieferantenseite sieht den Verweis nicht.
