# WT-01 Hypothesen, Zielwächter und Wert-Pipeline

Version 1.0 · Kapitel 8 · Paket K8-a · baut auf ST-01, WK-01, MS-01, HE-01 · Bildvorlagen: K8-Warengruppe, K8-Hypothese, K8-Mobil · KN-62, KN-63

## Ziel

Jeder Hebel einer Strategie ist eine Hypothese mit Wert, Sicherheit und prüfbaren Annahmen. Reziproq prüft die Annahmen und Ziele jeden Morgen und legt eine Abweichung in den Fokus, bevor sie teuer wird. Die Wert-Pipeline zeigt, wie viel vom Wert der Strategie schon beschlossen, umgesetzt und gesichert ist.

## Grundsätze

- Begriff in der Oberfläche: **Hypothese** und **Annahme**, nie „Wette“ (E-K8-2).
- Sicherheit setzt der Code aus Regeln (unten), nicht das Modell (G-6).
- Senken geschieht automatisch; Anheben nur mit Beleg und Bestätigung der verantwortlichen Person.
- Alles in `buyer_private`. Kein Lieferant sieht Hypothesen, Annahmen, Ziele oder die Pipeline.

## Hypothese

Behauptung in einem Satz; Wirkung je Größe (EBIT, Kostenvermeidung, Cash, Versorgung in %, Einzelquelle in %), nie verrechnet; Sicherheit hoch, mittel oder niedrig; Stand im Plan, gefährdet, bestätigt, offen, verworfen; verantwortliche Person; „kippt, wenn“; verknüpfte Ziele, Initiativen, Mandate, Vergaben. Entsteht aus Teil 3 und 4 der Strategie (ST-01): jeder übernommene Hebel wird eine Hypothese; der Strategie-Autor schreibt Hypothesen statt Hebellisten.

**Annahme:** prüfbare Bedingung mit Prüfregel (Feld, Vergleich, Wert oder Frist), Quelle (ERP, Wareneingang, Mail, Termin, Marktsignal, Lieferantenplan) und Frist. Stand je Lauf: im Plan (Beleg erfüllt), offen (Frist nicht erreicht, noch kein Beleg), verletzt (Regel nicht erfüllt oder Frist verstrichen; auch: ein Signal verschiebt eine Frist über die Grenze).

**Regel für die Sicherheit:** eine Annahme verletzt → niedrig; sonst zwei oder mehr offen nach Ablauf der halben Frist → mittel; sonst bleibt der Wert, den das Team bei der Freigabe gesetzt hat. Anheben schlägt Reziproq vor, wenn alle Annahmen im Plan sind und ein neuer Beleg vorliegt.

## Zielwächter

Je Ziel der Strategie (fünf Dimensionen) Ist, Planpfad und Stand: **im Plan**, **gefährdet** (Ist liegt mehr als 10 % des Abstands unter dem Planpfad oder eine verknüpfte Hypothese ist gefährdet), **offen** (kein Hebel greift noch). Ist-Werte aus den Daten der Kennzahl; Planpfad linear zwischen den Meilensteinen des Ziels, sofern das Team nichts anderes eingetragen hat.

## Wert-Pipeline

Je Wertart getrennt (G-3): **Potenzial** (Hypothesen mit Sicherheit hoch und mittel, Spanne), **beschlossen** (Initiativen R3), **umgesetzt** (R4), **gesichert** (R5, vom Controlling bestätigt; WK-01). Gezeigt wird EBIT; Kostenvermeidung und Cash als eigene Zeilen, wenn vorhanden. Versorgung und Einzelquelle sind keine Euro und stehen nie in der Pipeline.

## Ablauf

1. Täglich um 06:00 prüft `hypothesis.check_assumptions` alle Annahmen der gültigen Strategie und setzt den Stand (Erledigen, in Erledigt mit Beleg).
2. Wird eine Annahme verletzt, sinkt die Sicherheit, die Hypothese wird gefährdet, und es entsteht ein Fokus-Thema für Lead der Warengruppe und verantwortliche Person. Berührt die Hypothese Anteile, zeigt das Fokus-Thema auf die Mappe „Anteile anpassen“ (SZ-01), sonst auf die Hypothese.
3. Zielwächter und Pipeline werden im selben Lauf neu gerechnet.

## Seiten

**Warengruppe (`/warengruppen/<id>`), wenn eine Strategie gilt:** zusätzlich Wert-Pipeline, Hypothesen der Strategie (Code, Behauptung, Unterzeile mit Wert und kritischer Annahme, Sicherheit, Stand), Zielwächter, Abstand zu den Soll-Kosten (WZ-01), Vergaben (VG-01), Review (RV-01). Vor der Freigabe gilt die Ansicht aus ST-01.

**Hypothese (`/warengruppen/<id>/hypothesen/<code>`):** Behauptung, Wirkung, „kippt, wenn“; Annahmen mit Stand, Quelle, Frist; Verlauf der Sicherheit; was daran hängt; woher Reziproq es weiß; „Nur für euch“.

## Daten

```sql
CREATE TABLE hypothesis (
  id uuid PRIMARY KEY, category_id uuid NOT NULL, strategy_version_id uuid, strategy_item_id uuid,
  code text, claim text NOT NULL, effects jsonb,          -- je Größe: Art, low, high, Einheit; nie Summe
  certainty text CHECK (certainty IN ('hoch','mittel','niedrig')),
  state text CHECK (state IN ('im_plan','gefaehrdet','bestaetigt','offen','verworfen')),
  owner_person_id uuid, breaks_if text, links jsonb,
  space text NOT NULL DEFAULT 'buyer_private');

CREATE TABLE assumption (
  id uuid PRIMARY KEY, hypothesis_id uuid, code text, text text,
  rule jsonb NOT NULL,                                     -- Quelle, Feld, Vergleich, Wert, Frist
  due_at date, space text NOT NULL DEFAULT 'buyer_private');

CREATE TABLE assumption_check (
  id uuid PRIMARY KEY, assumption_id uuid, run_id uuid, checked_at timestamptz,
  state text CHECK (state IN ('im_plan','offen','verletzt')), evidence jsonb);

CREATE TABLE certainty_change (
  id uuid PRIMARY KEY, hypothesis_id uuid, from_level text, to_level text, reason text,
  by_run_id uuid, confirmed_by uuid, changed_at timestamptz);

CREATE TABLE goal_watch (
  id uuid PRIMARY KEY, strategy_item_id uuid, checked_at timestamptz, actual numeric, planned numeric,
  state text CHECK (state IN ('im_plan','gefaehrdet','offen')), reason text);

-- Sicht strategy_pipeline: je Warengruppe, Strategie-Version und Wertart vier Werte:
--   Potenzial   = Spanne aus hypothesis.effects mit certainty IN ('hoch','mittel')
--   beschlossen = Summe initiative.plan_value mit stage = 'R3' (je Wertart)
--   umgesetzt   = stage = 'R4'
--   gesichert   = value_booking.state = 'bestaetigt'
--   nie über Wertarten summiert; Versorgung und Einzelquelle nicht enthalten
```

## Werkzeuge

`hypothesis.check_assumptions` (Erledigen) · `goal.watch` (Erledigen) · `hypothesis.raise_certainty` (Vorschlagen; Anheben nur mit Bestätigung) · `hypothesis.update` (Mensch).

## Demo

Strategie Leiterplatten V3: H1 Laminat direkt (27 bis 63 T€, mittel, im Plan), H2 Moldau 20 % (Versorgung 2028, niedrig, gefährdet), H3 Bündeln (Versorgung, mittel, im Plan), H4 Mehrlagen (72 bis 108 T€, mittel, im Plan), H5 Kupferklausel (60 bis 90 T€, hoch, bestätigt), H6 Marktstandard (20 bis 30 T€, niedrig, offen). H2 Annahmen: A1 Erstmuster bis 31.03. (verletzt am 18.01.: Mail Moldau vom 15.01., Prüfung 31.05.), A2 Kapazität 1,8 Mio. € bis 30.06. (offen), A3 Vorserie ≤ 30 ppm (24 ppm, im Plan). Pipeline 18.01.: Potenzial 210 bis 310 T€, beschlossen 107 bis 137 T€, umgesetzt 0, gesichert 0. Ziel „Kapazität für den Anlauf 2028“ gefährdet.

## Fertig, wenn

- [ ] T8-01 Jede Hypothese hat mindestens eine Annahme mit Prüfregel, Quelle und Frist; ohne Annahme lässt sie sich nicht speichern.
- [ ] T8-02 Eine verletzte Annahme senkt im Morgenlauf die Sicherheit und erzeugt ein Fokus-Thema für Lead und verantwortliche Person; der Beleg steht in Erledigt.
- [ ] T8-03 Die Wert-Pipeline zeigt je Wertart getrennt, Potenzial nur aus Sicherheit hoch und mittel; Versorgung und Einzelquelle erscheinen nie in Euro oder in einer Summe.
- [ ] T8-14 Ein Lieferanten-Nutzer erreicht keine Hypothese, keine Annahme, keinen Zielwächter, kein Szenario, keine Soll-Kosten und kein Review (Abfrage, Suche, Frag, Agent).
- [ ] T8-WT1 Reziproq hebt eine Sicherheit nie ohne Bestätigung an.
- [ ] T8-WT2 Gleiche Daten ergeben denselben Stand aller Annahmen und Ziele.

## Nicht Teil

Wahrscheinlichkeiten in Prozent; Hypothesen ohne Strategie; Hypothesen beim Lieferanten.
